# 文档整理与更新

## 用途
按照仓库文档规范，对现有文档进行整理、查找、修正或新增。

## 触发条件
- 用户要求"整理文档"、"修复文档"、"更新文档"、"补充文档"、"新增文档"
- 代码变更后需要同步更新文档
- 发现文档断链、重复、缺失、过时等问题
- 新增模块/功能点后需要创建对应文档

## 前置阅读
执行任何文档操作前，**必须先读取** `.agent/rules/doc-standards.md` 了解完整的文档规范。

## 工作流程

### 场景 1：查找文档

1. 明确用户要找什么（功能点？集成？总览？编码规范？）
2. 按 `docs/` 目录结构定位目标文件
3. 使用 Glob 定位目标文件，返回路径和摘要

### 场景 2：修正文档（断链、过时、重复、错误）

1. 读取 `.agent/rules/doc-standards.md` §4
2. 定位问题文件
3. 根据问题类型选择修复策略：
   - **断链**：检查目标文件是否改名/移动，更新链接
   - **过时**：对照源码验证，更新接口签名/配置/行为描述
   - **重复**：验证新文件覆盖旧文件后，删除旧文件
   - **错误**：对照源码修正，`[推断]` 标注无法验证的内容
4. 如果涉及源码验证，先 Read 对应的 `.cs` 文件
5. 修复后更新相关索引（上级 README.md）

### 场景 3：新增文档

1. 读取 `.agent/rules/doc-standards.md` §3
2. 确认文档类型，放入对应 `docs/` 子目录（模块文档用单个 README.md，不再使用 6 件套）
3. 阅读相邻模块的同类型文件作为风格参考
4. 阅读对应源码，基于实际代码撰写内容（不凭空编造）
5. 文档应保持 30-60 行概览，不复制代码实现细节
6. 更新上级 README.md 索引

### 场景 4：清理旧文件/目录

1. 发现旧文件时，先验证新文件是否覆盖了旧内容
2. 如完全覆盖 → 删除旧文件
3. 如部分覆盖 → 先合并独特内容到新文件，再删除旧文件
4. 删除空目录

### 场景 5：整理后验证

- [ ] 文件命名与同域一致（模块用单个 README.md）
- [ ] 交叉引用链接有效（无死链）
- [ ] 上级 README 索引已更新
- [ ] 无旧文件残留
- [ ] 文档保持概览级别（≤ 100 行，无代码块复制）

## 关键原则

1. **源码是唯一事实源**：文档内容必须基于实际代码，不确定的地方标注 `[推断]` 或 `[待确认]`
2. **先验证再删除**：删除旧文件前，必须确认新文件已覆盖其内容
3. **保持一致性**：新增文档的命名和结构必须与同域已有模块一致
4. **索引同步**：任何文件增删都要更新对应的 README.md 索引
