# 2026-10-21 OpenCode 进程保活复用与准备链路优化验证

范围：OpenCode 运行时延迟优化的第一批落地——空闲进程保活复用（`OpenCodeProcessKeeper`，实测后默认关闭）、进程常驻 MCP 桥宿主、准备链路并行化、Skill 内容缓存、配置读缓存、版本不固定。实现要点见 [运行时文档](../integrations/opencode-runtime.md)，任务状态见 [任务清单](../planning/TODO.md)。

## 实测结论（Windows x64，真实 OpenCode 1.19.3，本地确定性模型，同机同探针）

| 配置 | 每轮总耗时（请求 → 末事件） | 稳定性 |
|---|---|---|
| 基线 `origin/dev`（每轮新进程） | 约 2.5 s（2.5–2.8） | 稳定 |
| 本分支默认（保活关闭，其余优化全部启用） | 约 2.5 s（2.4–2.6） | 稳定，与基线持平 |
| 本分支保活开启 | 首个追问轮 0.92 s（约 -63%），其后 2.0–2.7 s | 随保活进程数劣化（第 5 轮全新轮升至约 7.2 s） |

**保活默认关闭的原因**：实测保活进程空闲时存在约 1–2 CPU 核的持续空转与持续外呼（30+ 条对外 443 连接，经由本机代理，目标服务未完全归因）。该行为源于 OpenCode 1.19.3 harness 自身的空闲活动（会话服务/watcher/后台请求）：与平台侧 MCP 桥的存亡无关——已把桥重构为随进程常驻（端点不再死亡），空转依旧；多进程保活会拖慢整机，收益被抵消。保活机制保留为显式配置（`KeepAliveSeconds > 0`），确认目标版本空闲行为可接受后可开启。

## 实现：进程保活复用（默认关闭，机制保留）

- 复用键 = 会话归属（租户/用户/会话哈希）+ 启动身份（实际可执行文件、参数与受控环境哈希；覆盖模型端点/密钥、Agent 指令与 MCP/Skill 放行策略），不跨会话归属复用进程。
- 进程主目录（进程工作目录 + HOME/USERPROFILE/XDG/OPENCODE_CONFIG_DIR）随进程生命周期；每轮随机工作区（`t-*`）仅作为 ACP 会话 cwd，轮次结束即删除（失败时后台延迟重试）。保活进程主目录为 `p-*`，随进程销毁回收。
- 完整成功（`end_turn`）的轮次归还保活池；失败、取消、进程死亡、空闲超时、会话数（`MaxSessionsPerProcess`）或总量（`MaxKeptProcesses`）超限即销毁并回收主目录；后台清扫周期不超过 5 秒。
- 复用轮次跳过进程启动与 ACP initialize，`RuntimeStarted` 身份事件由缓存的对端身份发出；每轮仍新建 ACP session 与随机工作区。

## 实现：进程常驻 MCP 桥宿主（始终生效）

- 工具桥为宿主共享单例（上游 PR #242 方案，合并时采纳取代本 PR 的进程级桥宿主）：挂载主站端口或回退自建 loopback，每轮以独立 256 bit bearer 注册/吊销工具集；不再每轮构建监听站点，也不给 harness 留下死端点。本 PR 的跨轮工具隔离语义由上游"并发轮次独立注册"覆盖（真实 OpenCode 跨轮换工具回归测试保留）。

## 实现：准备链路优化

- `RuntimePreparation` 并行化：历史加载、平台工具发现与各 feature 工厂并行执行后按注册顺序合并；EF 仓储均按调用创建独立 DbContext；工厂同步/异步失败时已启动任务进入统一释放路径。
- `SkillPackageCache`：Skill 包按（租户、对象键、包 SHA-256）内容寻址缓存到进程级目录，staging 原子提交；追问轮次零下载，发布新包自然失效。未登记哈希的记录退回一次性目录随轮释放；条目上限 256。
- `McpConfigRepository` / `RuntimeProfileRepository` 内置 30 秒 TTL 读缓存（含负结果），写入/删除即时失效；跨进程最多 30 秒陈旧窗口。
- 版本不固定：Dockerfile 默认安装最新发布（构建参数可锁定），文档与测试提示去版本化；usage 断言改为版本无关语义（上下文占用口径或 null）。

## 验证

- 全解决方案回归（真实 OpenCode 开启）：**0 失败**。Runtime.Tests 含 7 项保活测试与 2 项桥租约测试（bearer/取消拒绝、跨轮工具轮换）；Engine.Tests 215/215（真实 HTTP/SSE → OpenCode → 平台工具 → 持久化 → 续聊）；Application.Tests 含 6 项 Skill 缓存测试（独立根目录，并行套件下连续三次全绿）；Framework.Tests 含 4 项配置缓存竞争测试（在途读取 vs 保存/删除/新增、负缓存）与仓储写失效测试；Architecture 14/14。
- 上表计时为一次性探针实测（同机、同 harness、5 轮），探针未保留在仓库；准备链路并行化与缓存未单独计时（收益取决于历史长度与启用 Skill/MCP 数量，行为由回归覆盖）。

## 评审修复（PR #243 review）

1. **Skill 缓存租约与安全淘汰**：`SkillPackageCache` 改为实例类型（DI 单例），轮次持 `Lease` 引用；引用获取与淘汰标记在同一锁内同步，下载/校验在锁外，只回收零引用条目；缓存根按进程隔离（含进程 ID），同进程多次构造共享一次性初始化，跨进程互不删除。
2. **配置缓存读写竞争**：`TenantEntryCache` 每键一个状态对象（代次 + 已发布值）；`Invalidate` 提升代次并清空，回填的代次检查与发布在同一临界区，失效前启动的在途读取不会回填旧值/旧负结果；补 4 项竞争测试（TCS 门控时序）。
3. **feature 所有权唯一登记**：`RuntimePreparation.CreateAsync` 以对象身份集合保证成功产物只进 `scope.Features` 一次，合并中途失败（provider/PrepareTool/重复工具名）与迟到成功任务都恰好释放一次；补 5 项测试（异步失败、provider 失败、PrepareTool 失败、重复工具名、迟到成功）。
4. **缓存测试隔离**：`SkillPackageCacheTests` 每测试独立根目录，断言只针对本测试路径；含"活跃租约在超限物化下不被淘汰"回归。

## 诊断过程中发现的存量问题（本 PR 未解决，待单独跟进）

1. **Windows 上宿主用户技能目录泄漏进"隔离"进程**：OpenCode 1.19.3 在 Windows 下无视平台设置的 HOME/USERPROFILE，扫描并加载了宿主用户 `C:\Users\<user>\.claude\skills`、`.agents\skills` 下 26 个技能（日志 `duplicate skill name`/`init count=26`）。与保活无关，属进程环境隔离在 Windows + 当前 OpenCode 版本的缺口；需上游确认 `homedir` 解析机制或平台侧进一步收紧。
2. **OpenCode 空闲进程持续外呼**：保活进程空闲时维持 30+ 条对外 443 连接并持续增长；本机经代理出网，目标服务未完全归因（疑似后台轮询）。阻碍保活默认开启，需上游跟进或部署侧评估。

## 环境偏差与限制

- 本机验证使用 npm 包内原生二进制（版本 1.19.3），经 `OPENAGENT_TEST_OPENCODE` 指定；已按版本无关语义收敛断言。
- 保活复用放宽了"每轮全新进程"的进程级隔离：同一会话在窗口内共享 harness 进程与状态目录缓存。会话、工作区、桥租约与 bearer 仍每轮独立；跨会话不共享。这不是操作系统沙箱，与既有边界声明一致。
- 未验收：生产并发容量下的内存驻留画像、多实例部署下配置缓存 30 秒陈旧窗口的产品影响、Skill 缓存跨进程并发（staging 原子提交已防交错，未跨进程压测）、其他 OpenCode 版本的空闲行为。
