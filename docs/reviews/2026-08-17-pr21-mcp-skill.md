# PR21 MCP 与 Skill 变更 Review

**Review 日期：** 2026-08-17
**基线：** `origin/main` `56301b01`
**PR：** [#21](https://github.com/philfanzhou/OpenAgent/pull/21)

## Review 结论

PR21 已从“平台自建能力实现”收敛为“官方 SDK + 平台策略层”：MCP 使用官方 C# SDK，Skill 使用 MAF 官方 provider；OpenAgent 新增的业务代码集中在配置、授权、包完整性、stdio 策略和隔离执行。真实端到端链路和 UI 均通过。

本轮完成实现相对合并最新 main 后的工作树为 56 个文件、`+2289/-34`；其中包含 3 张合计约 152 KiB 的脱敏 PNG 验收截图。大部分新增量来自独立沙盒 Host、确定性 E2E fixture、测试和三份中文交付文档，不是重复实现 MCP/Skill 协议。

当前未发现阻塞合并的已知缺陷。可合并前提是接受两项明确限制：MCP stdio 是可信宿主进程，不是沙盒；MAF 逐调用审批尚未接入 Chat，本版使用管理员逐 Skill 授权作为审批边界。

## 变更架构

| 层 | 变更 | Review 结果 |
|---|---|---|
| Contracts | Skill 脚本沙盒请求/响应/状态；Skill 资源与脚本计数、执行开关；MCP 运行时策略状态 | 纯数据契约，无基础设施依赖 |
| Core / MCP | stdio 开关、命令/环境/工作目录白名单；官方 transport | 修复 basename 绕过；保持 HTTP/SSE 行为不变 |
| Core / Skill | 包解压限额与计数；官方 provider；显式 runner；双重授权和路径校验 | 不在 Engine 进程执行脚本；请求结束删除 materialized 目录 |
| Sandbox Host | UDS API、低权限 Python、超时/输出/资源限制、审计日志 | 独立项目只依赖 Contracts；架构测试锁定边界 |
| Engine Host | MCP/Skill runtime 状态、逐 Skill 执行策略端点、默认配置 | 读写分别要求 `agent.config.read/write` |
| Docker | 独立无网络沙盒、只读根、能力与资源限额、UDS 共享卷 | 本地/受控环境基线；不等同强多租户隔离 |
| Chat UI | 独立 MCP/Skill 配置状态、脚本开关、协议版本；工具卡片分类 | MCP、SKILL、SKILL 脚本在会话中可辨识 |
| Tests | Core/Engine/Architecture/Sandbox 单测；官方 MCP + Skill E2E fixture；UI 单测与截图 | 覆盖拒绝路径、超时、截断、协议协商和真实工具循环 |

## 按文件组说明

### 契约与配置

- `Backend/src/OpenAgent.Contracts/Configuration/AgentConfig.cs`：目录元数据增加资源数、脚本数和管理员执行开关；Agent 仍只引用 Skill ID。
- `Backend/src/OpenAgent.Contracts/Mcp/McpConnectionTest.cs`：连接测试返回协商版本和 runtime policy，供 UI 解释安全语义。
- `Backend/src/OpenAgent.Contracts/Skills/SkillScriptSandbox.cs`：Core 与沙盒 Host 的唯一共享契约。
- `Backend/src/OpenAgent.Core/Capabilities/Mcp/McpExecutionOptions.cs`：新增环境变量与工作目录白名单。
- `Backend/src/OpenAgent.Core/Capabilities/Skill/SkillScriptSandboxOptions.cs`：集中脚本大小、输出、参数和超时限制。

### MCP 执行

- `Backend/src/OpenAgent.Core/Capabilities/Mcp/McpTransportFactory.cs`：保留官方 `StdioClientTransport`，平台只做 fail-closed 策略；绝对路径必须精确允许，裸命令不接受路径伪装。
- `Backend/src/OpenAgent.Engine.Host/Extensions/ManagementEndpointExtensions.cs`：暴露经过授权的 MCP runtime 状态，不返回密钥。
- `Backend/tests/OpenAgent.Core.Tests/Capabilities/McpTransportFactoryTests.cs`：覆盖默认禁用、basename 绕过、环境变量、工作目录与合法裸命令。
- `Backend/tests/OpenAgent.Core.Tests/Capabilities/McpToolFactoryTests.cs`：纳入最新协议版本。

### Skill 包与官方 provider

- `Backend/src/OpenAgent.Core/Capabilities/Skill/AgentSkillPackageArchive.cs`：流式限制解压总量和文件数，统计官方目录中的资源与 Python 脚本。
- `Backend/src/OpenAgent.Core/Capabilities/Skill/AgentSkillsProviderFactory.cs`：按绑定与 ACL materialize 文件，构建 MAF 官方 provider；只把已授权脚本交给显式 sandbox runner，并在 runner 内重新校验。
- `Backend/src/OpenAgent.Core/Capabilities/Skill/DisabledSkillScriptSandbox.cs`、`HttpSkillScriptSandbox.cs`：默认拒绝与 UDS/HTTP 适配分离。
- `Backend/src/OpenAgent.Core/Exten/CoreServiceExtensions.cs`：按配置注册唯一 sandbox 实现。
- `Backend/src/OpenAgent.Engine.Host/Skills/SkillPackageManagementService.cs`：上传时保存内容计数，脚本执行默认关闭。
- `Backend/tests/OpenAgent.Core.Tests/Capabilities/AgentSkillPackageArchiveTests.cs`、`Backend/tests/OpenAgent.Engine.Tests/Skills/SkillPackageManagementServiceTests.cs`：覆盖压缩包限额、计数和默认拒绝。

### 隔离执行服务

- `Backend/src/OpenAgent.SkillSandbox.Host/*`：只监听 UDS；root supervisor 仅负责降权，脚本以 uid 10001 和 Python isolated mode 运行；共享 stdout/stderr 总预算并终止超时进程树。
- `Backend/tests/OpenAgent.SkillSandbox.Tests/*`：覆盖参数/输出、超时、单流截断与双流合计上限。
- `Backend/tests/OpenAgent.Architecture.Tests/*`：锁定 Sandbox Host 只能依赖 Contracts。
- `docker-compose.yml`：声明无网络、只读根、tmpfs、capability、PID/内存/CPU 限制和 UDS 只读消费。

### 管理 UI 与会话呈现

- `Frontend/OpenAgent.Chat/src/types.ts`、`api.ts`：新增 runtime 状态和逐 Skill policy API。
- `Frontend/OpenAgent.Chat/src/App.vue`：MCP 与 Skill 保持独立配置页；展示风险边界、内容计数与授权开关；协议选项增加 `2026-07-28`。
- `Frontend/OpenAgent.Chat/src/messagePresentation.ts`、`components/ChatMessages.vue`：运行时工具名转换为 MCP、SKILL、SKILL 脚本用户标签。
- `Frontend/OpenAgent.Chat/src/api.test.ts`、`markdown.test.ts`：覆盖请求契约与展示映射。

### E2E 资产

- `Backend/tests/OpenAgent.E2E.Fixtures/*`：官方 MCP C# stdio Server、真实 Agent Skill 包与确定性 OpenAI-compatible 工具循环模型，仅供验收，不进入生产运行时。
- `Backend/OpenAgent.sln`：纳入 Sandbox Host、Sandbox Tests 和 E2E fixture，确保全量 build 能发现漂移。
- `docs/test-reports/assets/pr21/*`：设置页与会话截图，未包含明文 API Key。

## Review 中发现并已修复

| 发现 | 风险 | 修复 |
|---|---|---|
| PR21 基线落后且与最新 main 冲突 | 旧配置分发器与文档可能覆盖新主线 | 合并 `origin/main`，只人工解决配置 dispatcher 与 MCP 文档冲突 |
| stdio 允许路径只比较 basename | `/tmp/dotnet` 可伪装白名单命令 | 裸命令精确匹配；带路径命令只允许精确绝对路径 |
| Skill ZIP 未限制解压总量与文件数 | ZIP bomb、内存与对象存储放大 | 128 文件、4 MiB 解压总量、流式计数、重复/不安全路径拒绝 |
| MAF 默认工具审批无法由当前 SSE 回传 | `load_skill` 后工具循环中断 | 关闭未接入的逐调用审批，使用管理员逐 Skill 开关 + 沙盒；记录后续演进 |
| 测试模型把脚本参数包成字符串 | runner 无法按 SDK schema 解析 | 按官方工具 schema 传 JSON string array |
| `python3-minimal` 缺完整标准库 | 合法 Skill 的 `import json` 失败 | 沙盒镜像改为完整 `python3`，保持 isolated mode |
| stdout/stderr 分别限额 | 合计输出可达到配置的两倍 | 两流共享原子输出预算并在超限时终止进程 |

## 保留风险与建议

| 优先级 | 项目 | 说明 |
|---|---|---|
| P1（多租户开放前） | 强隔离 runtime | 普通容器共享内核；应评估 gVisor/Kata/Agent Sandbox 与每次执行实例化 |
| P1（远程部署前） | 远程 sandbox 认证 | `remote-http` 必须由 mTLS、服务网格或认证代理保护 |
| P2 | 用户逐次审批 | Chat 增加 MAF approval request/response 后恢复逐调用审批 |
| P2 | stdio 运维身份 | 配置 MCP stdio 等价于部署受信进程，应限制到平台管理员并配套镜像/包供应链治理 |
| P2 | 云 LLM 验收 | 本轮无外部模型凭据；需在目标环境补一次真实云模型工具选择回归 |

详细威胁模型和选型依据见 [MCP 与 Skill 执行安全调研](../integrations/mcp-skill-execution/RESEARCH.md)，执行证据见 [测试报告](../test-reports/2026-08-17-pr21-mcp-skill-e2e.md)。
