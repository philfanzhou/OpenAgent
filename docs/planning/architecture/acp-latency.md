# ACP 延迟优化

基线：dev `0f670f86`；日期：2026-10-28。实现与验收事实集中在 [OpenCode 运行时](../../integrations/opencode-runtime.md)。

## 耗时与改动

原路径每轮启动进程、创建工作区/session、重新传入历史。现在同一会话复用进程与固定工作区；历史检查点一致时，通过 ACP `session/resume` 延续同一个原生 session，只发送本轮新增输入。

创建和清理由一个保活池管理。默认空闲保留 300 秒、最多 16 个空闲会话，池满时移除最久未使用的空闲会话；正在执行的会话不参与淘汰。设 `KeepAliveSeconds=0` 可关闭。

## 授权和一致性

- 每轮重新授权、轮换 MCP bearer 和工具回调，旧凭证在轮次结束后失效。
- 平台保存成功后才能续用；版本冲突、手动压缩或工具 schema 变化时重建 session。
- 归属、启动配置或 Skill 内容变化时换新进程；失败、取消或过期统一回收。
- SDK 不支持 resume/close 或存在自定义上下文 Provider 时，使用完整历史新建 session。

## 验证结论

即时本地模型对照中，冷启动首字约 1656 ms，固定工作区的新 session 约 140 ms，原生 session 续接约 143 ms。后两者短文本延迟接近；保留每轮凭证轮换仍有 MCP 注册开销，19 ms 的固定凭证原型不代表本次实现。

本次同时保留原生多轮上下文、减少重复历史注入与代码量，沿用现有服务结构和 SDK。全量后端 1116 通过、25 环境门控跳过；真实模型端到端表现需在目标部署环境继续观察。任务状态见 [TODO](../TODO.md)。
