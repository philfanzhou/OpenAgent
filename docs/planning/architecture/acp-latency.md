# ACP 延迟优化

基线：dev `768a8c1e`；调研与实现日期：2026-10-28。

## 耗时在哪里

真实 OpenCode 1.19.3 + 本地即时模型，首字延迟中位数：

| 路径 | 首字 |
|---|---:|
| 原默认：每轮启动进程 | 1551 ms |
| 原进程保活：每轮新目录/session | 389 ms |
| 固定目录、每轮新 session 的原型 | 138 ms |
| 同 ACP session 连续追问的原型 | 19 ms |

这些数字用于比较框架开销，不含真实模型计算、平台存储和前端显示。

## 缺陷与本次改动

原来进程可以保活，工作区却每轮重建，OpenCode 的目录缓存无法完整复用；创建与清理分散在执行器和保活池。

本次把进程和工作区交给同一个保活池管理。追问复用固定 cwd；取消、失败或到期时统一回收。Skill 首次复制为独立副本，内容变化自动换新执行环境。租户、用户、会话、Agent 和配置分别隔离。

默认空闲保留 15 秒，最多 2 个空闲进程；可设 `KeepAliveSeconds=0` 关闭。工作区保留期间的本地文件会供同一会话追问继续使用。详细行为与验证见 [OpenCode 运行时](../../integrations/opencode-runtime.md)。

## 后续边界

改造后的完整驱动实测追问首字 p50 **138.7 ms**；全量后端 **1104 通过、25 环境门控跳过**。

当前每轮仍新建 ACP session、轮换工具凭证、传入平台历史。这保留现有授权与落库流程，避免增加跨轮状态机。19 ms 的 session 连续复用原型未并入本次实现；推进前需要解决每轮授权轮换、平台保存失败后的恢复和事件按轮排空。
